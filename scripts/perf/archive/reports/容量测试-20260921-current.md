# CozyCoffee 容量测试报告（2026-09-21）

## 测试对象与口径

- Git 提交：`050f357e8778721af62ff24c11cc09fcf4ba2f06`
- 负载工具：k6 1.5.0，固定到达率开放模型
- 正式轮次：每档 60 秒，共 3 轮，报告使用 3 轮中位数
- 运行主机：Docker Desktop，12 CPU、约 16.6 GiB 内存
- 服务资源：每个 Java 服务 1 CPU / 512 MiB
- 环境隔离：专用 Nacos / RocketMQ、独立 MySQL Schema、Redis DB 15
- 容量阈值：HTTP 失败率低于 0.1%、业务失败率低于 0.1%、丢弃迭代为 0
- 下单工作流：一次迭代包含购物车校验与创建订单，共 2 个 HTTP 请求

这两个数字适合 README 与简历使用：它们在本次隔离环境中有完整的三轮样本，且相对完成边界保留了响应时间余量。

| 场景 | 完成 / 阈值边界 | 边界表现 | 首次明确失败点 |

| 菜单读取 | 650 RPS | 3 轮共 117,002 次请求，零失败、零丢弃；P95 / P99 中位数为 5,018.653 / 5,174.745 ms | 675 RPS |
| 购物车校验 + 创建订单 | 60 TPS | 3 轮尝试 10,801 笔、创建 10,798 笔；失败率仍低于 0.1%，但 P95 / P99 已升至 4,805.290 / 6,107.847 ms | 65 TPS |

完成边界只表示系统在该环境中仍能完成绝大多数请求，不等于适合业务使用的容量。README 与简历采用 300 RPS / 25 TPS，避免把高延迟边界包装成稳定承载能力。
